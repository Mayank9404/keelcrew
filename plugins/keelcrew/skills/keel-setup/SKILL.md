---
name: keel-setup
description: One-time Keelcrew setup on this Mac (captain's name, Mate folder and repos, where tasks come from, team pack, Keelcrew board, checks), ending with this session running as the Mate
argument-hint: [Keelcrew board artifact URL]
disable-model-invocation: true
---

Set up Keelcrew for the captain, in this session, and finish as their running Mate in the same turn: the captain answers one message, clicks Install once and approves the Auto mode card, nothing else (no Terminal, no restart, no "start the crew"). It must run in the Mate folder: the folder that holds the git repos the crew works in. The plugin lives in `${CLAUDE_PLUGIN_ROOT}`; `keelctl` below means `node "${CLAUDE_PLUGIN_ROOT}/cli/keelctl.mjs"` until step 6 installs `~/.keelcrew/bin/keelctl`. Keep it short: one line per step done, and every question in step 2 asked at once.

1. **Look first, ask nothing yet.**
   - Repos: list the folders in this session's folder that hold a `.git` folder (a `.git` file is a worktree of another repo; skip it), and each one's base branch (`git -C <repo> symbolic-ref --short refs/remotes/origin/HEAD`, else `main` or `master`, else its current branch). None found: say the Mate folder must hold the repos the crew works in, and stop until they open this session in the right folder or name it.
   - Jira: check whether the Atlassian connector's tools are in this session (`getAccessibleAtlassianResources`, `searchJiraIssuesUsingJql`). If they are, call `getAccessibleAtlassianResources` for their sites and cloud ids.
   - The Mac: this is macOS (`uname`).
   - The helper: the board reaches this Mac through `keelcrew-local`, a local helper the Claude app runs. `keelctl doctor helper` says whether the app has it (a session's own tool list doesn't show helpers the app adds after the session started, so don't judge by that); its result decides step 3.
   - This session's model and effort (`get_session` with "self"): the Mate keeps them.
   - Scheduled jobs: `keelctl agents --json`, the agents with `runAs: "schedule"` except `scan` (the panel runs the Jira scan); all are off until the captain picks them.
2. **Ask, in one message** (offer the defaults so they can answer "yes"):
   - Their first name.
   - The repos found, with their base branches: is that right? A repo the crew shouldn't touch can be switched off, and a base branch changed, under board Settings → Tasks → Repos once the board is up; say so, and keep going.
   - A short team name for their pack (lowercase, e.g. their team or company), default their first name.
   - Where tasks come from: **the board** (New task, or tell the Mate here), or **Jira too**. Jira needs the Atlassian connector: with it, name the site found (or ask which one) and the default query, their open tickets (`assignee = currentUser() AND statusCategory != Done ORDER BY updated DESC`), which they can change. Without it, say how to add it (Claude app → Settings → Connectors → Atlassian) and that Jira can be added later; go on with the board.
   - Which scheduled jobs to turn on, default none: one line each from step 1, its name, its `schedule` labels and its summary in a few words. Say that each run is a session of its own on their plan, so pick only what they will read, and that any can be switched later under board Settings → Crew. Name what a job needs that this Mac lacks (comms needs the Outlook and Teams connectors, pm Datadog, support a source named in its settings).
   The questions are the message: never point to them as above or below. Don't ask about the Mate's model: it stays on this session's. As one line of this same message, say which model and effort that is, and that the Claude app starts no crew session above it (a Sonnet Mate keeps the whole crew on Sonnet), so they pick a higher model in this session's menu and the Mate's row under board Settings → Crew to lift it.
3. **Helper, if step 1 found none.** Right after their answer, say in one line to click **Install** in the dialog that opens for **keelcrew-local**, the Keelcrew helper (the app warns that a local extension can reach their whole Mac, which is true of any local helper), then run `keelctl helper bundle --open` with a 120-second timeout: it opens the Claude app's Install dialog for the Keelcrew helper, a desktop extension the app runs with its own node, with no restart, and waits for the click. When it says the helper is installed, go on and never ask about it again. When it times out, go on with steps 4 to 7 and settle it in step 8.
4. **Team pack.** `keelctl pack init <team> --lead-dir <this folder>`, adding `--jira-site <site URL>` and `--jql <query>` when they use Jira. It writes `~/.keelcrew/packs/<team>/pack.json` from their repos: base branches (protected, so the crew always works on a branch), the Mac's time zone, and Jira. Lint commands, PR checks and agent notes can be added to that file later. Never pick the example pack that ships with the plugin (`brinewick`): it describes a made-up company.
5. **Keelcrew board.** The built board ships in `${CLAUDE_PLUGIN_ROOT}/board/` (`index.html`, `capabilities.json`, `manifest.json`, the content-named modules and the stylesheet). Publish it as `${CLAUDE_PLUGIN_ROOT}/skills/keel-lead/publishing.md` says (Read it in full; when a publish batch runs in the background, its result wakes this session and setup goes on from there, with no message from the captain), with no `boardFiles`, so every file goes up. If $ARGUMENTS has a board link, publish to its `url`, which keeps its data; otherwise the first batch starts a new board. The capabilities are `db` with `settings` writable by admins only and `inbox` by the captain only, `mcp` with `host:keelcrew-local` and every tool the board calls, and `user`. Then, in one `ArtifactData` `batch`:
   - `crew/lead` (`update` with its `if_version` if it exists, else `set`): `pluginVersion` (from `${CLAUDE_PLUGIN_ROOT}/.claude-plugin/plugin.json`) and `boardFiles` (the manifest's `files`, plus each name in an existing `boardFiles` that the manifest lacks as `{"__delete__": true}`, since an update merges into the old map), so the Mate doesn't publish it all again.
   - `settings/main`: `set` it on a new board; on an existing one, `get` it first and `update` with its `if_version`, writing `org`, `intake` and `agents` back whole with your fields merged in (an update replaces each top-level field it names): `org.models.approved.lead` = `{model, effort}` of this session (step 1), so the Mate's start finds nothing to change; with Jira, `intake.jiraSite` = the site URL (ticket keys link to it); without Jira, `agents.scan.enabled` = `false` (no Jira scan); for each scheduled job they picked, `org.roles[<id>]` = `{enabled: true}` and `agents[<id>].enabled` = `true` (as the board's Settings → Crew writes a switch), and when the job's `department` is off by default (`ceo`, `marketing`, `support`), `org.departments[<department>].enabled` = `true`; `updatedAt` = now in epoch ms.
6. **Record it.** `keelctl setup --board <board URL> --owner <name> --lead-dir <this folder> --pack <team>`, adding `--cloud-id <the site's cloud id>` with Jira. It records the board, the Mate folder and its repos with their base branches, the pack and the cloud id, starts the Mate's notes, and installs `keelctl` and the `keelcrew-helper` link in `~/.keelcrew/bin`.
7. **Crew session settings and checks.** Run `~/.keelcrew/bin/keelctl doctor --fix`: it puts two Claude Code settings in `<Mate folder>/.claude/settings.local.json` (auto permission mode, so crew sessions never stall on a prompt; compacting at 600k tokens, so the Mate stays fast) and leaves the rest of that file alone. Tell them that in one line. Show each `warn` or `fail` it still reports.
8. **Helper, if step 3 timed out.** Run `keelctl helper bundle --open` once more (same timeout). Only if that times out too, ask whether the dialog showed up: if it shows an error or their organization blocks extensions, the fallback is a line in Terminal that quits the app, adds the helper to its config and opens it again, `~/.keelcrew/bin/keelctl helper install --restart`; after it, they come back to this session and say "go on".
9. **Become the Mate, now.** For the mode, call `set_session_permission_mode` with `session_id: "self"` and `mode: "auto"` (Auto keeps the crew from stalling on prompts) and say in one line to approve the card it shows; if it's refused, say to pick **Auto** in the mode menu. Then, in this same turn, read `${CLAUDE_PLUGIN_ROOT}/skills/keel-lead/SKILL.md` and do its Start (the captain asked to start the crew by running setup): register, read the config and the board, bring the watches in step, and handle any open board items. If Start left a start card waiting, call its start buttons (`mcp__ccd_turn__wrap_up`, as keel-lead says) first. End with exactly three lines and nothing more (no bullets, no recap): the board link; the crew is running and this session is the Mate; how work starts (add a task on the board with New task, or tell the Mate here; an engineer starts from the **Start <KEY>** button that **Open the Mate session** on its Start card brings up at the bottom of this chat, and the first engineer start in each repo asks them to trust that folder once; board Settings → Crew has a no-click choice for agents).
